# 2026-10-21 — Phases 1–2: environment, data, benchmark metric

- Upstream ships prebuilt wheels for torch 2.10 / CUDA 13 / cp312 (`mamba-ssm 2.3.2.post1`, `causal-conv1d 1.7.0`). The env is pinned to those (`pyproject.toml`, extra `kernels`).

## Data (details in `docs/data_manifest.md`)

- DNALongBench contact-map data comes from Harvard Dataverse doi:10.7910/DVN/AZM25S (CC0), MD5-verified.
- Akita's window coordinates come from Akita's own bucket, because the DNALongBench `targets/` folder has none.

### Finding 1 — the 4 H3 lines are not processed like the 5 training lines

`extra_data.complete/options.json` has `kernel_stddev: 0`, i.e. no Gaussian smoothing, while Akita's five were smoothed with σ = 1 (Akita paper). Everything else matches (log O/E, clip 2, offset 2, 2,048 bp).

Consequences for H3:
- Both H3 arms (pretrain + fine-tune vs. scratch) are trained and scored on the same unsmoothed targets, so the comparison stays fair.
- But a model pretrained on smoothed maps starts with a smoothness prior the targets lack. That works *against* the pretrained arm, so it is conservative for H3.
- Absolute SCC/PCC on the four lines are not comparable with the five.

**Options for the user** (not settled):
- (a) Use the targets unchanged (CLAUDE.md: "target unchanged") and report the difference as a limitation. **Recommended.**
- (b) Smooth the four lines' targets with σ = 1 to match. This is a target transform, which CLAUDE.md forbids unless it is applied identically to prediction and target.

### Finding 2 — the H3 split is clean

`scripts/check_h3_overlap.py`:
- The four lines' valid/test windows overlap 0 Akita training windows.
- No Akita valid/test window overlaps their training windows.
- The two parts share the same 354 contigs; only the strides differ (train 262,144 bp; valid/test 32,768 bp for the four).

The H3 design (protocol §5) therefore holds as written.

### Finding 3 — the benchmark's "SCC" is not HiCRep's SCC (needs a decision)

DNALongBench `scripts/metrics.py::scc`:
- weights stratum k by `N_k * var(arange(N_k)) / N_k**4` ≈ 1/(12·N_k);
- HiCRep (Yang et al. 2017) weights it by `N_k * sqrt(var(r1/N_k)·var(r2/N_k))` ≈ N_k/12.

So the benchmark's weights are ∝ 1/N_k: they **upweight the sparse long-distance strata**, the opposite of HiCRep. The likely cause is a missing square root and dividing by N⁴ instead of N². It also skips HiCRep's 2D smoothing, and its PCC (CNN `train.py`) is pooled over all values of the test set, not computed per window.

Implemented in `src/hifold/eval/metrics.py`:
- `scc_benchmark`: a verbatim port. A unit test checks it against a copy of the original.
- `scc_hicrep`: faithful HiCRep weights, with optional smoothing h (default 0).
- `pcc_window` and `pcc_pooled`.

**Decision needed.** Protocol §4.3 says SCC is HiCRep's SCC *and* is computed "with the same implementation and parameters as the benchmark", which is now a contradiction. Options:
- (a) Primary = `scc_benchmark`, for comparability with published Akita/Caduceus numbers; `scc_hicrep` always reported alongside, with the discrepancy stated in Methods.
- (b) Primary = `scc_hicrep`; benchmark SCC reported only for the reproduction check.

The two can rank models differently, because one emphasises long-range strata and the other short-range. Pre-register the choice before any model is scored.
