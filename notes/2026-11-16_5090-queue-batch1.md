## Reading
- Every model built on the HiFold code path (HiFold, the matched Transformer/CNN baselines and both ablations) stayed at SCC ≈ 0 with PCC ≈ 0.087 for all seeds. That is the level of a map that carries only the distance profile, i.e. no sequence information (cf. `2026-10-23_g1-profiling-reference.md`: the mean map gives SCC ≈ 0). Only the separate Akita implementation learned.
- This looks like a training failure in shared HiFold-side code or settings, not a scientific negative result. Diagnosed on 2026-11-17: see "Diagnosis" below.
- HiFold-family models were never trained to completion before this programme; only Akita seed 0 had run locally.

## Diagnosis (2026-11-17, from the runs' metrics.jsonl and local tests on the RTX 5050)
- **Training losses are identical across models.** At the same seed and step, hifold_paper, ablation_norc, ablation_nomixer, baseline_attention and baseline_conv log the same loss to 3–4 decimals (seed 1, step 70,000: 0.34016 / 0.34016 / 0.34017 / 0.34014 / 0.34014). Different networks giving the same loss means none of them uses the sequence: all predict the distance profile only. No NaN anywhere. Akita's losses differ (it learns).
- **Memorisation test** (scratchpad `overfit.py`: 4 training windows, 400 steps, AdamW 3e-4, paper config). Distance-only floor on these windows (best per-cell, per-diagonal constant): 0.1575.
  - HiFold as built: 0.1611 → **0.1576**. It cannot memorise 4 windows.
  - Akita on the same windows: training loss → 0.102, below the floor. The data and the loss are fine.
- **Cause** (activation and gradient probe, scratchpad `gradflow.py`). Gradients reach every layer (tower 0.2–1.7, head P/Q 0.75). The positional variation of the features collapses through the conv tower: the std over bins, relative to the total std, falls from 0.25/0.30 (stem) to 0.07/0.57 (tower10) and 0.048/0.37 (to_model). The tower normalises **per position over channels** (RCLayerNorm) after GELU + max-pool, so each channel drifts to a near-constant level along the sequence, and every bin looks the same to the head. Akita's tower uses BatchNorm, per channel over positions, which removes these constant levels.
- **Test of the cause.** The same memorisation run with one added per-channel normalisation over positions after the tower (experiment only, by monkeypatch; RC-equivariant because the statistics are per channel over all bins): 0.2186 → **0.0676**, far below the floor and below Akita.
- Memorisation is necessary but not sufficient. Whether the fix generalises is shown only by validation SCC in a real run.

## Akita seed 0: RTX 5050 vs RTX 5090 (same config hash; config files differ only in run_root)
Both runs follow the same course: validation HiCRep SCC stays ≤ 0.16 until step ~45,500, jumps to ~0.31–0.34 at step 49,056, then swings between evaluations (local 0.427 → 0.414 → 0.469; 5090 0.387 → 0.378 → 0.252 → 0.376 → 0.368). Seeds 1 and 2 jump later (56,064 and 52,560–63,072). The 0.469 vs 0.387 gap is within this late-training instability, not a hardware effect.
**Open point for the protocol (not decided):** Akita leaves its plateau only in the last third of the 70,080-step budget and is still unstable at the end, so the reproduction may be under-trained. A weak baseline would weaken H1. Options to discuss before registration: a longer budget for Akita, or early stopping on validation as in the published Akita. To be decided by the user.
